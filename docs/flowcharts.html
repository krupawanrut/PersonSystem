ผังงานระบบประเมินบุคลากร

ผังงานตามความต้องการของผู้ใช้ 4 กระบวนการหลัก ครอบคลุมการเข้าสู่ระบบ และการทำงานของผู้ใช้งานทั้งสามบทบาท ได้แก่ ฝ่ายบุคลากร ผู้รับการประเมิน และกรรมการผู้ประเมิน พร้อมแผนภาพภาพรวมระบบแบบ Use Case, Class Diagram ของโครงสร้างระบบทั้งหมด และการออกแบบ RESTful API

1.1

ผังงานระบบการเข้าสู่ระบบ

ตรวจสอบบัญชีผู้ใช้ บังคับเปลี่ยนรหัสผ่านเมื่อเข้าใช้งานครั้งแรก แล้วนำทางตามบทบาทผู้ใช้

1.2

ผังงานกระบวนการของฝ่ายบุคลากร

ตั้งค่าการประเมิน เพิ่มข้อมูลผู้ใช้งาน มอบหมายกรรมการ และติดตามผลจนปิดรอบประเมิน

1.3

ผังงานกระบวนการของผู้รับการประเมิน

กรอกหลักฐานและประเมินตนเองให้ครบทุกตัวชี้วัด ก่อนตรวจสอบผลและส่งออกรายงาน

1.4

ผังงานกระบวนการของกรรมการผู้ประเมิน

ตรวจหลักฐาน ให้คะแนนตามตัวชี้วัด บันทึกร่าง แก้ไขได้จนพอใจ แล้วลงนามส่งผล

1.5

ผังงานภาพรวมของระบบทั้งหมด (System Overview — Use Case Diagram)

แสดงผู้ใช้งานทั้ง 3 บทบาท และฟังก์ชันการทำงานทั้งหมดของระบบในภาพเดียว เพื่อให้เห็นขอบเขตการทำงานของแต่ละบทบาทอย่างชัดเจน

2.4

Class Diagram โครงสร้างระบบทั้งหมด

โครงสร้างคลาสหลักของระบบ ความสัมพันธ์แบบสืบทอด (Inheritance) ระหว่างผู้ใช้งานสามบทบาท และความสัมพันธ์แบบประกอบ (Composition) ระหว่างหัวข้อ ตัวชี้วัด การมอบหมาย และคะแนน

4.1–4.2

การออกแบบ RESTful API สำหรับใช้งานในระบบ

ออกแบบ Endpoint ตามหลัก RESTful แยกตาม Resource ใช้ HTTP Method ให้ตรงความหมาย (GET อ่าน, POST สร้าง, PUT แก้ไข, DELETE ลบ) และตั้งชื่อ Endpoint เป็นคำนามพหูพจน์ที่สื่อความหมายและสอดคล้องกันทั้งระบบ

Auth — การเข้าสู่ระบบ

MethodEndpointคำอธิบายใช้โดยบทบาท
POST/api/auth/loginเข้าสู่ระบบด้วย username/password รับ JWT tokenทุกบทบาท
PUT/api/auth/passwordเปลี่ยนรหัสผ่านของตนเอง (บังคับเมื่อเข้าใช้งานครั้งแรก)ทุกบทบาท
POST/api/auth/logoutออกจากระบบ (invalidate token)ทุกบทบาท

Users — ผู้ใช้งาน

GET/api/users?role=รายชื่อผู้ใช้งานทั้งหมด กรองตามบทบาทได้ฝ่ายบุคลากร
GET/api/users/{id}ข้อมูลผู้ใช้งานรายคนฝ่ายบุคลากร
POST/api/usersเพิ่มผู้รับการประเมิน/กรรมการผู้ประเมินใหม่ฝ่ายบุคลากร
PUT/api/users/{id}แก้ไขข้อมูลผู้ใช้งานฝ่ายบุคลากร / เจ้าของบัญชี
DELETE/api/users/{id}ลบผู้ใช้งานฝ่ายบุคลากร
PUT/api/users/{id}/password-resetคืนค่ารหัสผ่าน (Reset Password)ฝ่ายบุคลากร

Evaluation Topics — หัวข้อการประเมิน

GET/api/topicsรายการหัวข้อการประเมินทั้งหมดทุกบทบาท
GET/api/topics/{id}รายละเอียดหัวข้อการประเมินทุกบทบาท
POST/api/topicsสร้างหัวข้อการประเมินใหม่ พร้อมช่วงเวลาเปิด–ปิดฝ่ายบุคลากร
PUT/api/topics/{id}แก้ไขหัวข้อ/ช่วงเวลาเปิด–ปิดการประเมินฝ่ายบุคลากร
DELETE/api/topics/{id}ลบหัวข้อการประเมินฝ่ายบุคลากร

Indicators — ตัวชี้วัด

GET/api/topics/{topicId}/indicatorsรายการตัวชี้วัดภายใต้หัวข้อนั้นทุกบทบาท
POST/api/topics/{topicId}/indicatorsเพิ่มตัวชี้วัดใหม่ (ชื่อ, น้ำหนัก, รูปแบบ, หลักฐาน)ฝ่ายบุคลากร
PUT/api/indicators/{id}แก้ไขตัวชี้วัดฝ่ายบุคลากร
DELETE/api/indicators/{id}ลบตัวชี้วัดฝ่ายบุคลากร

Assignments — การมอบหมายกรรมการ

GET/api/assignments?evaluatorId=&evaluateeId=รายการมอบหมาย กรองตามกรรมการ/ผู้รับการประเมินฝ่ายบุคลากร / กรรมการ
POST/api/assignmentsมอบหมายกรรมการให้ประเมินผู้รับการประเมิน พร้อมบทบาทฝ่ายบุคลากร
PUT/api/assignments/{id}แก้ไขบทบาทกรรมการ (ประธาน/กรรมการร่วม)ฝ่ายบุคลากร
DELETE/api/assignments/{id}ยกเลิกการมอบหมายฝ่ายบุคลากร

Evaluation Details & Evidence — รายละเอียดและหลักฐาน

GET/api/indicators/{id}/detailsรายละเอียดประกอบการประเมินของตัวชี้วัดนี้เจ้าของข้อมูล / กรรมการที่เกี่ยวข้อง
POST/api/indicators/{id}/detailsเพิ่มรายละเอียดประกอบการประเมิน (เพิ่มได้หลายรายการ)ผู้รับการประเมิน
PUT/api/details/{id}แก้ไขรายละเอียดที่เคยกรอกผู้รับการประเมิน (เจ้าของ)
DELETE/api/details/{id}ลบรายละเอียดผู้รับการประเมิน (เจ้าของ)
POST/api/details/{id}/evidenceอัปโหลดไฟล์หลักฐาน PDF/รูปภาพ หรือแนบ URL (multipart/form-data)ผู้รับการประเมิน

Self-Score & Scores — การให้คะแนน

PUT/api/indicators/{id}/self-scoreกรอก/แก้ไขคะแนนประเมินตนเองผู้รับการประเมิน
GET/api/assignments/{id}/scoresดูคะแนนทั้งหมดของการมอบหมายนี้ (รายตัวชี้วัด)กรรมการ / ฝ่ายบุคลากร
PUT/api/assignments/{id}/scores/{indicatorId}ให้คะแนน/แก้ไขคะแนนร่างตามตัวชี้วัดกรรมการ
PUT/api/assignments/{id}/commentบันทึกความเห็นสรุปภาพรวม (ร่าง)กรรมการ
POST/api/assignments/{id}/signลงนาม (แนบลายเซ็น) และยืนยันส่งผลการประเมินกรรมการ

Reports — รายงานผล

GET/api/evaluatees/{id}/reportรายงานผลการประเมินรายบุคคลเจ้าของ / ฝ่ายบุคลากร
GET/api/evaluatees/{id}/report/pdfExport รายงานผลเป็นไฟล์ PDFเจ้าของ / ฝ่ายบุคลากร
GET/api/reports/summaryสรุปภาพรวมสำหรับ Dashboard (ความคืบหน้า, สถานะ)ฝ่ายบุคลากร

สิทธิ์การเข้าถึงตามบทบาท (RBAC)

Resourceฝ่ายบุคลากรผู้รับการประเมินกรรมการผู้ประเมิน
หัวข้อ / ตัวชี้วัดCRUD ทั้งหมดอ่านอย่างเดียวอ่านอย่างเดียว
ผู้ใช้งานCRUD ทั้งหมดอ่าน/แก้ไขเฉพาะตนเองอ่าน/แก้ไขเฉพาะตนเอง
การมอบหมายCRUD ทั้งหมดอ่านเฉพาะของตนเองอ่านเฉพาะของตนเอง
รายละเอียด/หลักฐานอ่านอย่างเดียวCRUD เฉพาะของตนเองอ่านเฉพาะที่เกี่ยวข้อง
คะแนนประเมินอ่านอย่างเดียวอ่าน/แก้ไขคะแนนตนเองCRUD เฉพาะที่ได้รับมอบหมาย

มาตรการความปลอดภัยอื่น ๆ

  • เข้ารหัสรหัสผ่านด้วย bcrypt ก่อนบันทึกลงฐานข้อมูล ไม่เก็บรหัสผ่านแบบ Plain Text
  • กำหนดอายุ JWT Token (เช่น 2 ชั่วโมง) หมดอายุแล้วต้องเข้าสู่ระบบใหม่
  • Middleware ตรวจสอบลายเซ็น (Signature) และอายุของ Token ทุกคำขอ ก่อนตรวจสอบสิทธิ์ตามบทบาท (RBAC)
  • ตรวจสอบความถูกต้องของข้อมูลนำเข้าด้วย express-validator ทุก Endpoint ที่รับข้อมูล (ป้องกัน Injection)
  • จำกัดชนิดและขนาดไฟล์ที่อัปโหลดเป็นหลักฐาน (PDF/JPG/PNG สูงสุด 5 MB ต่อไฟล์)
