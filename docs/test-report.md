## 7.1 ทดสอบระบบ Login (Username/Password ถูก-ผิด)

| เคสทดสอบ | ผลลัพธ์ที่คาดหวัง | ผลจริง |

**ผล: 4/4 ผ่าน**

## 7.8 มีการใช้งาน GitLab Server

⚠️ **ยังไม่เสร็จ — ต้องดำเนินการเพิ่มเติม**

ปัจจุบัน repository นี้ตั้งค่า remote ไว้ที่ GitHub (`github.com/krupawanrut/PersonSystem`) ไม่ใช่ GitLab ตามที่เกณฑ์ระบุ

**สิ่งที่ต้องทำ:** เพิ่ม remote ไปยัง GitLab Server (เช่น GitLab ของสถานศึกษา หรือเครื่องแม่ข่ายที่ทางศูนย์สอบจัดเตรียมไว้ในวันแข่งขัน) แล้ว push code เข้าไป คำสั่งตัวอย่าง:

```bash
git remote add gitlab <URL ของ GitLab Server ที่ได้รับ>
git push gitlab main
```

*หมายเหตุ: ต้องมี URL/บัญชี GitLab Server จากผู้ดูแลการแข่งขันก่อนจึงจะดำเนินการขั้นนี้ได้*

## 7.9 แสดงผลของระบบบนเครื่องคอมพิวเตอร์แม่ข่ายที่จัดเตรียมไว้ให้

⚠️ **ต้องดำเนินการในวันแข่งขันจริง** — ข้อนี้ขึ้นกับเครื่องแม่ข่ายที่ผู้จัดการแข่งขันเตรียมไว้ให้หน้างาน ซึ่งไม่สามารถทดสอบล่วงหน้าได้จากสภาพแวดล้อมนี้

**สิ่งที่เตรียมไว้ให้พร้อมสำหรับขั้นตอนนี้:** ระบบถูก containerize ด้วย Docker Compose ครบทั้ง Frontend/Backend/Database ไว้แล้ว (`docker-compose.yml`) ดังนั้นบนเครื่องแม่ข่ายที่มี Docker Desktop เพียงรัน:

```bash
docker compose up -d --build
```

ก็จะได้ระบบที่ทำงานเหมือนกับที่ทดสอบในเอกสารนี้ทุกประการ โดยไม่ต้องติดตั้ง Node.js/MariaDB แยกต่างหากบนเครื่องนั้น

## 7.10 ทดสอบการแสดงผลแบบ Responsive (มือถือและ Desktop)

ทดสอบจริงด้วยการปรับขนาด viewport ผ่าน Chrome DevTools Protocol (`Emulation.setDeviceMetricsOverride`) ไม่ใช่แค่ย่อหน้าต่างเบราว์เซอร์:

| หน้า | Desktop 1440px | มือถือ 390px |
|---|---|---|
| `/login` | ✅ แสดงผลถูกต้อง ไม่มี horizontal scroll | ✅ พาเนลแบรนด์ย้ายขึ้นด้านบน ฟอร์มเต็มความกว้าง อ่านง่าย |
| `/dashboard` | ✅ Sidebar + เนื้อหา 2 คอลัมน์ | ✅ Sidebar ย้ายขึ้นบน, stat tile เรียงเป็นคอลัมน์เดียว |
| `/evaluatee/self-evaluation` | ✅ | ✅ รายการตัวชี้วัดและ progress bar แสดงผลครบถ้วน |

ตรวจสอบเพิ่มเติมด้วยโค้ด: `document.documentElement.scrollWidth > clientWidth` ทุกหน้า ทุกขนาดจอ **ไม่มีหน้าใดเกิด horizontal scroll**

**ผล: ผ่านทั้ง Desktop และ Mobile**
